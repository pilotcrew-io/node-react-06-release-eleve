# Produit · Livrer une réservation reprenable

**Atelier 06/06 · 4 h 30 · nr-06-release**

Après une réservation confirmée, une personne recharge le navigateur. L’équipe veut retrouver la référence et le montant en relisant le serveur. Si le processus a été redémarré et que la réservation a disparu, l’interface doit l’expliquer sans créer discrètement une nouvelle réservation.

Ce dépôt contient les instructions, les mémos et les espaces de travail. **Le code est à construire ; aucune solution terminée n’est fournie dans le dépôt élève.** Les acquisitions précédentes sont reprises avant la séance selon [Day 0](DAY0.md).

## À la fin de la séance

- Découper une demande produit en critères d’acceptation et risques.
- Reprendre une référence par lecture serveur sans réserver à nouveau.
- Traiter une référence perdue au redémarrage avec un message honnête.
- Rendre ADR, runbook, notes de version et plan de progression.

## Déroulé de 270 minutes

| Séquence | Minutes |
| --- | --- |
| Critères et risque de reprise | 25 |
| Plan et décision d’architecture | 40 |
| Tranche verticale de reprise | 70 |
| Incidents et vérifications | 50 |
| Revue, démonstration et documentation | 55 |
| Bilan et remise | 30 |

Répartition cible de cette séance : **180 min frontend / 90 min backend**, tests et revue de chaque couche inclus. Sur le cursus : **18 h frontend et 9 h backend**. Cette dominante React est un choix pédagogique, pas un ratio chiffré attribué à l’annonce.
